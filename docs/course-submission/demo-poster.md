## Six-minute core demo

| Time | Presenter action | Audience sees / claim supported |
| --- | --- | --- |
| 0:00–0:45 | Explain the presenter workflow and show the architecture diagram. | Native desktop plus authenticated services; the model proposes within deterministic boundaries. |
| 0:45–2:15 | Open the four-slide local manifest; navigate, highlight a formula, zoom and reset. | Actual local presentation controls and recovery on redistributable fixtures. Explicitly say the region was selected manually. |
| 2:15–3:15 | Run one offline replay and open its aggregate report; show the second partition's committed result. | 21-frame synthetic contract check; show provenance/scope and `release_gate: false` next to the numbers. The 100% result is not real-world accuracy. |
| 3:15–4:15 | Show a negation/injection case description from the evaluation guide and the corresponding regression coverage. | Safe no-action/allowlist contract, using authored input/replies. No claim of a new live attack test. |
| 4:15–5:15 | Show the 28 November native evidence row with PowerPoint zoom **blocked**, then manual reset. | Real runtime failure and preserved recovery. Without Office, show the dated evidence table rather than pretending to execute a native action. |
| 5:15–6:00 | Summarize measured versus unmeasured results and the threat model. | Honest support boundary, future measurement plan, QR/link to the exact package revision and reproduction guide. |

Before presenting, perform the credential-free steps on the actual demo machine.
Keep a local source ZIP and aggregate reports available if installation/network fails.
A screenshot or table is labelled recorded evidence, not a live run. If the app fails,
record the failure, use the documented artifacts to explain the boundary and do not
replace it with an unlabelled animation.

## Optional connected extension

Budget a separate three minutes only after the operator confirms ready services, saved
source/analysis and eligible actions. With an informed speaker: explicitly start capture,
enable suggestions, request direct navigation, then discuss a distinct contextual topic.
Show a negated request, manual override and undo. Distinguish deterministic navigation
from a Jev choice. Stop capture/end the session visibly.

Repeat PDF and native PPTX independently if claiming both. Lack of Office, missing
verification, provider outage or a wrong action stays in the case record. Do not bypass
guards or silently switch an unavailable PPTX case to a PDF export. Follow the
[voice runbook](../voice-navigation-acceptance.md); this plan supplies no live acceptance.

## Poster content specification

Suggested title: **Buddy: speech-guided slides with constrained, recoverable actions**.
Use six readable panels, with a source/revision label beside each quantitative result:

| Panel | Content |
| --- | --- |
| Problem and user | Presenter attention divided between talk and visuals. Intended benefit, with no measured workload-reduction claim. |
| Agent loop | Fresh speech/current slide → bounded menu → Jev proposal or no action → deterministic checks → native executor → presenter override/undo. Explicit commands bypass intent inference. |
| Architecture and trust | Diagram from the report; server-side credentials/ownership, private storage, separate validator/runtime, provider disclosures. |
| Evidence | Fresh synthetic replay 21/21 per partition, labelled contract agreement. Historical provider result 87.5% / 1,020 synthetic-text sentences with source/scope. PDF and PPTX execution results shown separately. |
| Failure and limits | PowerPoint foreground-blocked zoom; wrong/missed semantic actions; no independent human holdout or current repeated speech-to-visible p50/p95. Synthetic timing/cost fields are excluded from a live-performance chart. |
| Reproduce and next evidence | Link/QR to reviewed commit, package index, install/run steps and finalization checklist. Team/course credits and a dated provenance note. |

Use a table instead of an accuracy comparison chart when sample populations/commits
differ. Do not put a single “100% accurate” headline above synthetic results, draw zero
cost bars for missing billing, or imply native PowerPoint support on macOS. No private
deck, transcript, account identifier, cloud console secret or provider diagnostic appears
on the poster. Use project-authored fixtures for any screenshot.
